# 代码注释与阅读顺序

代码注释只解释“为什么这样做”和边界条件，不逐句翻译代码。建议按下面顺序结合面试准备：

1. `启动项目.py` / `启动真实模型.py`：环境变量、应用工厂、服务入口。
2. `suite/app.py`：上传、检索、问答、SSE、异步任务接口。
3. `suite/rag.py`：extract → split_units → ingest，再看 retrieve → context → answer_stream；重点读 BM25/RRF/重排的块注释。
4. `suite/core.py`：Store 的连接与事务、Provider 的 Embedding/聊天/流式请求、本地模型降级。
5. `static/stream.js` → `app.js` → `ui.js`：SSE 分包读取、待校验草稿、完成/失败、即时排版与来源定位。
6. `tests/`：每个测试的目的注释，分清离线替身、状态断言和真实模型效果的证据范围。

词项、模型 token、向量维度与片段 ID 在注释中分别解释；引用 ID 校验不等于语义支持验证。650/100、候选数、预算等只是当前实现参数，不写成普遍最优。

验证：`pytest` 35 项通过；`node tests/test_stream_format.js`、`node tests/test_stream_client.js` 通过；`evaluation/eval_metrics.py` 输出四种策略指标。通过测试不等于真实模型准确率。
