# 面试讲解（职业教育知识库RAG）

## 一、3 分钟讲法

**背景（30 秒）**：把课件（PDF/Markdown）变成可追问的知识库，回答必须能点回原文页码或章节。

**难点（40 秒）**：检索质量与“可核验”。答得漂亮但没有依据，比拒答更糟；
表格和代码被切碎后，检索到了也读不懂。

**做法（60 秒）**：
1. 解析：PDF 保留物理页码，Markdown 按标题切章节。
2. 分块：结构感知——表格、代码围栏整块保留并补章节名；纯文字走 650/100 滑动窗口。
3. 检索：BM25 + bge 向量两路，RRF 融合（只看名次，避免两种分数量纲不同），
   再用 bge-reranker 重排前 8–16 个候选。
4. 生成：只给模型检索到的片段，要求每个事实后引用 `[片段ID]`；回答后校验 ID 是否属于本轮检索，
   越界或缺失直接拦截。检索为空时明确拒答。
5. 工程：文档版本 + backend 标识隔离（换模型不会混用旧向量），热点问题缓存，异步入库任务。

**结果（30 秒）**：35 项 pytest；11 篇语料（2 篇课件 + 9 篇干扰）22 题，
hybrid_rerank 的 Recall@5 0.944、MRR 0.627；无答案题全部召回到内容，靠生成端拒答兜底。

**边界（20 秒）**：小规模全量检索、无 OCR、无用户体系；评测是自建小样本，数字不宜外推。

## 二、追问预案

| 问题 | 回答要点 | 代码位置 |
|---|---|---|
| 为什么不用纯向量？ | 关键词对编号、术语更稳；向量对改写更稳；RRF 融合两路名次，成本低 | `retrieve` |
| RRF 的 k 为什么是 60？ | 经验值，主要作用是压低头部差距；本项目中影响不大，没有调参宣称 | `retrieve` |
| 重排后 MRR 为什么降？ | 重排把部分正确页从第 1 挪到第 2–3，换更多正确页进前 5；目标是覆盖面 | README 评测表 |
| 引用怎么保证不编？ | 生成后抽取 `[id]`，与本次检索结果的 ID 集合比对，越界即拒绝返回 | `answer_stream` |
| 文档更新怎么办？ | 同名文档版本 +1，整批片段原子替换；失败保留旧版本 | `ingest` |
| 换 Embedding 模型？ | `documents.backend` 记录模型与维度，检索只取当前 backend 的片段；换模型后跑 `重建索引.py` | `backend` 属性 |
| 大文件上传卡住？ | `/documents/async` 后台线程 + `task_id` 轮询；任务表有 200 条上限 | `app.py` |
| 缓存会不会读到旧答案？ | 缓存 key 含文档版本号，ingest/delete 时自增并清空 | `suite/cache.py` |
| 为什么全量扫不建 ANN？ | 几百片段毫秒级；超过 1 万块显式报错；Milvus 模式已留接口 | `retrieve` / `milvus_store.py` |
| 怎么做鉴权？ | `APP_TOKEN` + `X-API-Key`，页面“访问口令”写入 localStorage | `require_token` |

## 三、诚实边界

- 引用 ID 合法 ≠ 语义一定支持；`citation_support` 只是词面重合提示。
- 评测语料只有 2 篇真课件，数字说明的是“这套检索在这批题上有效”，不是生产准确率。
- 云端 Milvus 与 Docker 在这一版没有复验，README 已如实标注。
